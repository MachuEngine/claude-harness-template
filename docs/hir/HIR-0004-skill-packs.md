# HIR-0004 — 스택별 범용 스킬을 스킬 팩으로 제공

- 상태: 채택
- 도입일: 2026-11-11 (v0.4.0)
- 도입 근거: 개발자 요청. 첫 적용 프로젝트에서 백엔드·프론트엔드·디자인 스킬 4개를 만들어 반복해서 썼고, 그중 디렉터리 구조, 설정 파일, 검사 연결, 일반 규칙은 다른 프로젝트에서도 그대로 쓸 수 있었다.

## 발견한 문제
- 첫 적용 프로젝트에서 스킬을 단계마다 새로 쓰고 고쳤다. 새 프로젝트가 같은 스택을 쓰면 같은 작업(설정 파일 작성, 통합 테스트 skip·CI 실패 규칙, 트랜잭션 범위 세션, IME 가드, 대비 계산 절차 등)을 다시 해야 한다.
- 스킬 안에 범용 규칙과 프로젝트 전용 규칙(도메인, 설계 번호, 브랜드 브리프)이 섞여 있어서, 다른 프로젝트로 복사하면 전용 문장을 하나씩 걸러 내야 한다.
- 실제로 반복된 사례: 통합 테스트가 환경 변수 없이 조용히 건너뛰는 문제를 막는 규칙, 루트 `.gitignore` 규칙(`runs/`)이 소스 폴더(`frontend/src/runs`)를 가린 사례, 한글 IME 조합 중 Enter 전송.

## 개선안
| 장치 | 내용 |
| --- | --- |
| copier 다중 선택 질문 `skill_packs` | `python-backend`, `react-frontend`, `ui-design` 중 고른 팩의 스킬만 `.claude/skills/<스킬>/`에 생성. 폴더 이름 조건식을 쓴다 |
| 템플릿 소유 등록 | 고른 팩의 스킬 폴더를 `owned-files.txt`에 추가. 프로젝트에서 직접 고치면 기존 알림 훅과 `check.sh` 경고가 그대로 동작한다 |
| 프로젝트 보충 규칙 | `.claude/project-skills/<스킬>.md`(프로젝트 소유). 범용 스킬이 첫머리에서 "있으면 먼저 읽고, 충돌하면 그쪽이 우선"이라고 안내한다 |
| 예시 파일 | 스킬 `reference/`에 복사해 쓸 설정·코드 예시. 이름 끝을 `.example`로 해서 lint·테스트 도구가 읽지 않게 한다 |

- `frontend-design`은 Anthropic 원본을 바이트 단위로 그대로 넣고, 템플릿 테스트가 SHA-256으로 확인한다. 프로젝트 보충 안내는 원본 대신 `NOTICE.md`와 `CLAUDE.md`에 둔다.
- 첫 적용 프로젝트 전용 내용(도메인 규칙, 설계 번호, 승인 화면 고유 규칙, 브랜드 브리프)은 템플릿에 넣지 않았다. 해당 프로젝트의 `.claude/project-skills/`로 옮길 대상이다.

## 대안
| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 스킬을 항상 설치 | 스택이 다른 프로젝트에 맞지 않는 규칙이 들어가고, 스킬 설명이 맥락을 차지한다 |
| 팩마다 별도 템플릿 저장소 | 하네스 공통 파일과 버전이 따로 놀아 `copier update`가 둘로 나뉜다 |
| Claude Code 플러그인으로 배포 | 프로젝트 저장소에 스킬이 남지 않아 code-reviewer가 Read로 읽을 수 없고, 하네스 버전과 함께 고정되지 않는다 |
| 범용 스킬을 프로젝트에서 직접 고쳐 쓰기 | 다음 `copier update`에서 충돌이 쌓이고 개선이 다른 프로젝트로 가지 않는다(HIR-0002와 같은 문제) |
| `_exclude`에 조건식을 넣어 팩 제외 | `_exclude`를 지정하면 copier 기본 제외 목록을 덮어쓴다. 폴더 이름 조건식이 copier가 문서화한 방법이다 |

## 검증
- 템플릿 테스트(`tests/test_template.sh`): 팩 없음 → `.claude/skills/` 없음·소유 목록 변화 없음, 전체 팩 → 36개 파일, `python-backend`만 → 17개, `ui-design`만 → 5개. 각각 생성 파일 목록과 `owned-files.txt` 항목을 정확히 비교
- frontend-design `SKILL.md`·`LICENSE.txt`: 템플릿 파일 SHA-256이 원본과 같고, 생성 파일이 템플릿 파일과 바이트 단위로 같다
- 전체 팩 프로젝트에서 `scripts/check.sh` 통과(커밋 전·후), 스킬 파일 직접 수정 시 경고, `.claude/project-skills/` 추가는 경고 없음
- `copier update --data skill_packs=[...]`로 팩 추가, 빈 목록으로 제거
- 예시 코드는 첫 적용 프로젝트의 실제 구현에서 이름만 일반화했다. 템플릿 작업 중 임시 폴더에서 Python 예시는 ruff·ruff format·mypy strict, TypeScript 예시는 tsc·ESLint·Prettier와 SSE 구독 예시 단위 테스트를 통과했다. 이 검사는 템플릿 테스트에 넣지 않았다(의존성 설치가 필요하다)

## 알려진 한계
- 예시 파일의 의존성 버전은 `<버전>` 자리표시라, 실제로 설치해 동작하는지는 쓰는 프로젝트가 확인해야 한다.
- 기존 프로젝트의 `CLAUDE.md`는 갱신되지 않는다. 팩을 추가하면 스킬 경로를 직접 적어야 한다.
- 이미 같은 이름의 스킬 폴더가 있는 프로젝트에 팩을 추가하면 copier가 덮어쓸지 묻는다. 전용 내용을 먼저 `.claude/project-skills/`로 옮겨야 한다.
- code-reviewer Bash 훅은 `npm`을 허용하지 않는다. 프론트엔드 검사는 `scripts/check.sh`로만 돌릴 수 있다.
