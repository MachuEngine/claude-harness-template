# HIR-0002 — 템플릿 소유 파일 수정 시 템플릿 반영 알림

- 상태: 채택
- 도입일: 2026-11-10 (v0.2.0)
- 도입 근거: 개발자 요청. 하네스는 프로젝트를 진행하면서 개선되는데, 프로젝트 안의 복사본만 고치고 템플릿 저장소 반영을 잊으면 다른 프로젝트가 개선을 받지 못하고 다음 `copier update`에서 충돌이 쌓인다.

## 발견한 문제
- 템플릿 소유 파일은 프로젝트에도 복사본이 있어서, 작업 중에 프로젝트 쪽 복사본을 바로 고치기 쉽다.
- `WORKFLOW.md`의 개선 절차는 규칙일 뿐이라, 지키지 않아도 아무것도 알려 주지 않는다.

## 개선안
| 장치 | 잡는 경우 | 동작 |
| --- | --- | --- |
| PostToolUse 훅 (`template_drift_notice.py`) | Claude가 Edit·Write로 템플릿 소유 파일을 고칠 때 | 사용자에게 `systemMessage` 알림, 메인 세션에 `additionalContext`로 반영 제안 요청. 세션당 파일별 1회 |
| `harness-check.sh` 경고 | 에디터·Bash 등 모든 경로의 수정. 검사를 실행할 때 | 마지막 커밋 이후 바뀐 템플릿 소유 파일 목록을 경고. `.copier-answers.yml`도 바뀌었으면 `copier update`로 보고 경고하지 않음 |

- 템플릿 소유 파일 목록은 `.claude/harness/owned-files.txt` 한 곳에 두고 두 장치가 함께 읽는다.
- 둘 다 알림만 하고 작업이나 검사를 막지 않는다. 프로젝트 전용으로 잠시 고치는 경우도 있어서, 차단하면 정상 작업을 방해한다.

## 대안
| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 템플릿 소유 파일 수정을 PreToolUse 훅으로 차단 | 급한 수정이나 실험까지 막는다. 판단은 사람이 하도록 알림만 한다 |
| `check.sh`에서 경고 대신 실패 처리 | 템플릿 반영 전 상태로 커밋하는 것이 자연스러운 경우가 있다(템플릿 반영을 다음 단계로 진행) |
| 템플릿 버전과 파일 내용을 직접 비교 | 검사 때마다 템플릿 저장소에 접근해야 해서 오프라인·CI에서 불편하다 |
| 메모리나 프롬프트로만 안내 | 규칙만으로는 강제되지 않는다는 점이 이번 문제의 원인이다 |

## 검증
- 훅 단위 테스트: 템플릿 소유 파일 7건 알림, 프로젝트 파일·외부 경로 8건 무알림, 세션 내 중복 알림 없음, 잘못된 입력에도 종료 코드 0
- 템플릿 테스트: 변경 없음 → 경고 없음, 직접 수정 → 경고, 경고가 검사를 실패시키지 않음, `.copier-answers.yml`이 함께 바뀌면 경고 없음

## 알려진 한계
- 훅은 Edit·Write 도구만 잡는다. Bash로 고친 경우는 `check.sh`를 실행해야 알 수 있다.
- `check.sh` 경고는 커밋 전 변경만 본다. 이미 커밋한 직접 수정은 잡지 못한다.
